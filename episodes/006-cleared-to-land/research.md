# Research Brief — Episode 006: The Intent Layer Arrives

All quotes below were verified against sources; where a primary page returned 403 to my fetcher, I note that the quote is corroborated across multiple independent transcriptions rather than a single blog.

## A. Current state (recent, ~April–July 2026)

**Spec-driven tooling has gone from manifesto to shipped product in the last quarter.**

- **GitHub Spec Kit** — release **0.11.0 (June 16, 2026)** now integrates 30+ agents (Copilot, Claude Code, Cursor, Gemini CLI, Codex). Its loop is `Spec → Plan → Tasks → Implement`, each phase a Markdown artifact feeding the next. MIT-licensed, agent-neutral, currently the most-adopted approach. ([github.com/github/spec-kit](https://github.com/github/spec-kit), [github.github.com/spec-kit](https://github.github.com/spec-kit/))
- **AWS Kiro** — reached **general availability May 7, 2026** as a replacement for Amazon Q Developer. The GA-defining feature for your thesis: **property-based testing for spec correctness** and checkpointing — i.e., trying to build a partial machine-oracle for the spec itself. ([kiro.dev/blog/general-availability](https://kiro.dev/blog/general-availability/), [kiro.dev/docs/specs](https://kiro.dev/docs/specs/))
- **Tessl** — the purest "spec-as-source" bet (~$125M raised; code stamped `// GENERATED FROM SPEC – DO NOT EDIT`). Worth the skepticism: on **Jan 29, 2026** it **pivoted** to "the package manager for agent skills" and rebranded as an "Agent Enablement Platform"; its core Framework reportedly **still isn't GA** after ~9 months of private beta. Good "hype vs. shipped" contrast. ([tessl.io](https://tessl.io/), [CodeMySpec review](https://codemyspec.com/blog/tessl-review))
- **Martin Fowler's site** ran a three-tool comparison (Kiro / Spec Kit / Tessl) — the establishment blessing that SDD is now a real category, not a vendor slogan. ([martinfowler.com/.../sdd-3-tools](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html))

**Practitioners who ship, not pundits:**
- **Sean Grove (OpenAI)**, "The New Code," AI Engineer World's Fair 2025 — the intellectual spark. Verified quotes (corroborated across the InfoCaptor and lawwu transcriptions; primary pages 403'd my fetcher): *"The other 80 to 90% is in structured communication"*; *"structured communication is the bottleneck"*; and the memorable jab that keeping generated code while discarding the prompt is *"like you shred the source and then very carefully version control the binary."* His framing elsewhere: **"code is just a lossy projection of intent."** ([the-decoder.com](https://the-decoder.com/code-is-just-a-lossy-projection-of-intent-according-to-openai-researcher-sean-grove/), transcript at [lawwu.github.io](https://lawwu.github.io/transcripts/8rABwKRsec4.html))

**Skepticism / limits (write well about failure modes):**
- **Arcturus Labs, "Why Spec-Driven Development Breaks at Scale"** (Oct 17, 2025) — argues big specs inherit natural language's imprecision, so the formalization burden *moves* rather than disappears. ([arcturus-labs.com](http://arcturus-labs.com/blog/2025/10/17/why-spec-driven-development-breaks-at-scale-and-how-to-fix-it/))
- The concrete **underspecification** failure: an undefined button color yields green in one generation, red in the next; LLMs "produce plausible continuations" of whatever you *didn't* say. Specs describe the happy path thoroughly and edge cases barely. (summarized in multiple 2026 SDD critiques above)
- **36Kr's** sharp reframe: this "new paradigm" is arguably **the return of waterfall** — "listen to the PM and write requirement documents." A useful needle to thread. ([eu.36kr.com](https://eu.36kr.com/en/p/3388182127870345))
- **Simon Willison** (Feb 2026) has moved past "vibe coding," emphasizing **tests as the specification language** and hoarding working code as recombination material — a pragmatic counter to spec-maximalism. ([simonw.substack.com](https://simonw.substack.com/p/agentic-engineering-patterns))

## B. Deeper-context concepts

- **Shuvendu Lahiri (Microsoft Research), "Intent Formalization: A Grand Challenge for Reliable Coding in the Age of AI Agents"** (March 2026). The **verified** central quote (from the MS Research publication page): *"since there is no oracle for specification correctness other than the user, we need semi-automated metrics that can assess specification quality."* He defines the **intent gap** as *"the gap between informal natural language requirements and precise program behavior"* and names the real chokepoint: *"the central bottleneck is validating specifications."* This is your keystone — the formal statement that intent is the one pipeline node with no machine oracle. ([microsoft.com/research](https://www.microsoft.com/en-us/research/publication/intent-formalization-a-grand-challenge-for-reliable-coding-in-the-age-of-ai-agents/), [arxiv.org/abs/2603.17150](https://arxiv.org/abs/2603.17150))
- **Fred Brooks, "No Silver Bullet"** (1986) — the 40-year-old version of the same claim, verbatim: *"The hardest single part of building a software system is deciding precisely what to build… For the truth is, the client does not know what he wants."* Pairs perfectly with Lahiri: agents didn't create the intent problem, they just removed every other bottleneck around it. ([worrydream.com PDF](https://worrydream.com/refs/Brooks_1986_-_No_Silver_Bullet.pdf))
- **Verification vs. validation** — the distinction your arc has been building toward: verification asks "did we build it right" (has oracles: tests, types, proofs); validation asks "did we build the right thing" (oracle = the user, only). Lahiri's "no oracle" line is literally a statement that *validation cannot be automated.* Callback fuel for episode 004.
- **Karpathy, "Software 3.0"** — YC AI Startup School, **June 17, 2025**: natural language as the primary programming interface, *"vibe coding,"* and the older but load-bearing line *"The hottest new programming language is English"* (originally his tweet, Jan 2023). The optimistic pole your episode should pressure-test. ([latent.space/p/s3](https://www.latent.space/p/s3), [tweet](https://x.com/karpathy/status/1617979122625712128))

**Quote worth using (Grove, verified across transcriptions):** *"In the near future, the person who communicates most effectively is the most valuable programmer."*

## C. The surprising / fresh angle

The genuinely fresh 2026 material — and the piece that makes this a payoff episode, not a rehash — is that **people are now trying to build the missing intent artifact directly**, and hitting the exact wall Lahiri names.

- **"Lore: Repurposing Git Commit Messages as a Structured Knowledge Protocol for AI Coding Agents"** (Ivan Stetsenko, independent, **March 2026**, [arxiv.org/abs/2603.15566](https://arxiv.org/abs/2603.15566)) coins the term you want: the **"Decision Shadow"** — *the reasoning behind a commit that the diff discards: the constraints, rejected alternatives, and forward-looking context.* Lore stores that as git trailers, queryable by any agent. This is your "captain's log of intent," already implemented, needing no new infrastructure. It's the direct answer to episode 005's tease: capture it, version it, keep it.

The fresh, unstated point: **everyone is racing to give intent an oracle it can't have.** Kiro adds property-based tests *for the spec*; Tessl generates code *from* the spec; Spec Kit stages spec→plan→tasks. Every one of these is an attempt to push verification further upstream — and every one still terminates at a human saying "yes, that's what I meant." The tools can make the spec *precise* (verification), but precision is not correctness (validation). You can formally verify a spec against itself forever and never learn whether the spec was *right*. That's not a gap the tooling is closing; it's the one node that's now the whole job. The surprising inversion: as agents absorb construction *and* verification, the intent artifact — the captured, versioned conversation — becomes the only thing a human still uniquely owns, and the only thing with no test that can grade it but the user.

---

**Connective tissue (the spine):** For five episodes the constraint has been climbing upstream — from psychological safety, to people, to review, to verification, and last week to a four-day build that produced a plausible-but-unvalidated demo: a touch-and-go, never landed. This week it lands. The Theory of Constraints move is now complete: agents have subordinated construction and much of verification, exposing intent as *the* bottleneck — and Lahiri gives it a name and a proof that it has no machine oracle. So the spine is: **when the machine can build anything and check anything except whether it was the right thing, the engineer's job collapses to specifying, capturing, and validating intent — and the intent itself becomes the artifact worth versioning.** Spec Kit / Kiro / Tessl are the industry admitting this in tooling; Lore and the ADR revival are the first attempts to make intent durable; Brooks and Grove bracket it in time (1986's "deciding what to build is the hard part" meets 2026's "code is a lossy projection of intent"). The plane finally lands not when the code compiles, but when the only oracle that matters — the user — says "yes, that was the intent." Everything upstream was just taxiing.
